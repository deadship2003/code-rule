## LIF-003: Major Hazardous Operations Require Prior Consent [Process Standard · runtime phase | Effective 2026-09-07]

> Origin: 2026-09-07 requirement — if a command is irreversible and has
> major impact on system security or information security, it must
> obtain consent before execution; operations that would interrupt the
> session count as major hazardous too, because the user may be remote —
> once the connection is lost, all further interaction is affected.

Scope: all commands and system operations initiated by Claude in any
session, any project.

### Implementation Rules

- Defining "major hazardous": irreversible + major impact on system
  security or information security. Typical: mass deletion/overwrite
  (rm -rf on system paths, dd, mkfs), root-level permission overhauls
  (chmod/chown -R), destructive firewall/network changes, deletion or
  exfiltration of key and credential files.
- Operations that would interrupt the session are **treated as major
  hazardous operations**: restarting/killing the process chain hosting
  this session (claude daemon, Telegram/WeChat bridge services),
  `wsl --shutdown`, remote host reboots, network cuts the session
  depends on.
- Before execution, state in the conversation the exact command to be
  run and its expected impact, and obtain explicit consent; when unsure
  whether an operation is major, always ask first — better to over-ask.
