## LIF-001: All Text in English [Process Standard · universal coding | Effective 2026-09-07]

> Origin: 2026-09-07 requirement "all comments should be written in
> English", widened the same day by follow-up to full globalization —
> every manual / text / related annotation / description reorganized in
> English during refactors, nothing exempted. Amended 2026-09-08:
> three scoped exemptions (vendored third-party trees, realistic test
> fixtures, runtime user-facing locale copy) confirmed by the owner.

Scope: ALL text produced in or for any IT development project, in any
language and any artifact — code comments, commit messages,
documentation, manuals, README, UI copy, and business/client
deliverables (deviation tables, quotations, etc.). Text generated or
modified by Claude follows this equally.

### Implementation Rules

- **Code comments, full coverage**: inline comments, block comments, and
  doc comments (Go doc comment / Python docstring / Doxygen / JSDoc etc.)
  are all written in English.
- **Git commit messages**: the commit message (subject + body) is always
  in English; together with LIF-004 (commit identity) it forms the dual
  commit constraint — identity Deadship2003 / language English.
- **All other text — no exemptions beyond the Exemptions section**:
  manuals, documents, README, UI copy, and client-facing deliverables
  (deviation tables, quotations, etc.) are all in English — full
  globalization; the only carve-outs are the scoped exemptions
  registered at the end of this entry.
- **Legacy handling**: refactoring is a full-English conversion point —
  when a legacy project is refactored, ALL of its non-English content
  (comments, docs, manuals, texts) is reorganized into English in that
  pass; new projects are English from day one.

### Exemptions (amended 2026-09-08, owner-confirmed)

Scoped carve-outs from full globalization — each recorded with its
trade-off rationale per LIF-002:

- **Vendored third-party trees** (e.g. `src/third_party/mihomo`):
  comments and strings inside a vendored upstream subtree stay in the
  upstream language. Rewriting vendored code breaks upstream merges
  and future syncs; the exemption protects maintainability. First-
  party code is never covered by this clause.
- **Realistic test fixtures**: fixture data that represents real user
  data (e.g. native-language node names in a subscription parser's
  tests) stays as-is — fixtures are data, not prose, and translating
  them would weaken fidelity to production input. Test names,
  assertions, and comments remain English.
- **Runtime user-facing locale copy**: strings shown to the product's
  end users at runtime (bot replies, app UI messages) may follow the
  product's audience locale when it serves a non-English user base.
  Everything developers and operators read — code comments,
  documentation, manuals, README, commit messages, CLI operator
  output, logs — is always English.

> Related: LIF-004 (Git commit identity) — both are repository-level
> universal standards covering language and identity as two dimensions;
> comments inside the LIF-008 examples are bound by this entry as well.
