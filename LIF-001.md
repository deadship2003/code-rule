## LIF-001: All Text in English [Process Standard · universal coding | Effective 2026-09-07]

> Origin: 2026-09-07 requirement "all comments should be written in
> English", widened the same day by follow-up to full globalization —
> every manual / text / related annotation / description reorganized in
> English during refactors, nothing exempted.

Scope: ALL text produced in or for any IT development project, in any
language and any artifact — code comments, commit messages,
documentation, manuals, README, UI copy, and business/client
deliverables (deviation tables, quotations, etc.). Text generated or
modified by Claude follows this equally.

### Implementation Rules

- **Code comments, full coverage**: inline comments, block comments, and
  doc comments (Go doc comment / Python docstring / Doxygen / JSDoc etc.)
  are all written in English.
- **Git commit messages**: the commit message (subject + body) is always
  in English; together with LIF-004 (commit identity) it forms the dual
  commit constraint — identity Deadship2003 / language English.
- **All other text — no exemptions**: manuals, documents, README, UI
  copy, and client-facing deliverables (deviation tables, quotations,
  etc.) are all in English — full globalization, nothing exempted.
- **Legacy handling**: refactoring is a full-English conversion point —
  when a legacy project is refactored, ALL of its non-English content
  (comments, docs, manuals, texts) is reorganized into English in that
  pass; new projects are English from day one.

> Related: LIF-004 (Git commit identity) — both are repository-level
> universal standards covering language and identity as two dimensions;
> comments inside the LIF-008 examples are bound by this entry as well.
