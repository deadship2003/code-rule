## LIF-008: Unified Project Build and Environment Script Standard [Technical Standard · engineering build | Effective 2026-09-07]

Scope: repository build and environment preparation for ALL projects in
any IT development context, any language; for purely interpreted
languages (Python / Node etc.) with no compile concept, `build.sh`
wraps their packaging/publish steps (`python -m build`,
`npm run build`, etc.) — the three-file structure is unchanged.

### Implementation Rules

**Core principle: standardize the external interaction interface (file
names, entry commands, artifact directory identical across all
projects); choose the internal build tool per project as needed.** The
three files sit fixed at the repository root:

| File | Role | Responsibilities |
|---|---|---|
| `setup.sh` | Environment & dependency prep | system packages / toolchains / library dependencies, permission prechecks, submodule fetch, config generation; **never compiles artifacts** |
| `build.sh` | Top-level build entry | calls make, writes no low-level compile commands itself; can clean and rebuild |
| `Makefile` | Low-level build abstraction layer | provides the 9 standard targets; CMake/Cargo/Go/Node all wrapped inside; developers may use native make directly |

- C/C++: CMake underneath, wrapped and invoked by Makefile / build.sh.
- Golang: native go build underneath, **a Makefile wrapping the
  standard targets is still mandatory — making people memorize raw go
  build flags is forbidden**.
- Purely interpreted languages: a Makefile is equally mandatory,
  wrapping fmt / lint / test / packaging.

**Standard Makefile targets (unified semantics across all projects):**

| target | semantics |
|---|---|
| `all` | default target = build |
| `build` | compile and produce executables |
| `clean` | delete build artifacts and build caches |
| `distclean` | deep clean = clean + build dirs, vendor, .env, temp files; **never clears global shared caches** (go modcache, cargo registry, etc. — cleaning project A must not harm projects B/C/D) |
| `install` | file-layer install: copy artifacts to system/output directories (see "install semantic layering") |
| `uninstall` | file-layer uninstall |
| `fmt` | code formatting |
| `lint` | static analysis / code style checks |
| `test` | unit tests |

Example (Go; note that make syntax requires TAB indentation on recipe
lines):

```makefile
BINARY_NAME=panoxy
OUTPUT_DIR=bin

.PHONY: all build clean distclean fmt lint test install uninstall

all: build

build:
	mkdir -p $(OUTPUT_DIR)
	CGO_ENABLED=0 go build -o $(OUTPUT_DIR)/$(BINARY_NAME) ./cmd/$(BINARY_NAME)

clean:
	rm -rf $(OUTPUT_DIR)

distclean: clean
	rm -rf vendor .env

fmt:
	gofmt -w ./

lint:
	golangci-lint run ./...

test:
	go test -v ./...

install:
	cp $(OUTPUT_DIR)/$(BINARY_NAME) $(HOME)/.local/bin/

uninstall:
	rm -f $(HOME)/.local/bin/$(BINARY_NAME)
```

Example (C/C++ wrapping CMake, showing the differing targets; fmt /
lint / test / install / uninstall follow the same template via
clang-format / clang-tidy / ctest / cmake install):

```makefile
BUILD_DIR=build
OUTPUT_DIR=bin

.PHONY: all build clean distclean

all: build

build:
	mkdir -p $(BUILD_DIR)
	cd $(BUILD_DIR) && cmake .. && $(MAKE)

clean:
	rm -rf $(OUTPUT_DIR)

distclean: clean
	rm -rf $(BUILD_DIR)
```

**setup.sh contract:**

1. Environment dependencies only, never compiles code: system package
   install (apt / pacman / brew), `git submodule update --init
   --recursive`, `go mod download` / `cargo fetch` / `npm install`,
   permission / group / directory prechecks.
2. Idempotent: repeated runs never error; already-installed
   dependencies are skipped.
3. Exit policy: a missing dependency that fails to install → `exit 1`
   terminates the flow.
4. `./setup.sh --check`: only verifies the environment is ready,
   installs nothing (CI preflight mode).

**build.sh contract:**

1. Top-level build entry; prefers calling make internally, writes no
   low-level compile commands itself.
2. Unified interface (LIF-005 subcommand form): `build` (default
   release build; with `--debug` = symbols kept, no optimization; with
   `--clean` = clean before building) / `clean` (clear bin/, keep
   dist/) / `install` (local smooth deploy) / `package` (multi-arch
   archives + checksums; `--arch` selects the target) / `help`.
3. Artifacts output uniformly to `./bin/`, identical across all
   projects.
4. Never installs system dependencies (that belongs to setup.sh).
5. Disambiguation: `./build.sh build --debug` acts on the **build
   script** (producing a debug artifact), while LIF-007 `prog run
   --debug` acts on the **program itself** (foreground run) — different
   objects; the debug workflow = `./build.sh build --debug` to produce,
   then `prog run --debug` to run in the foreground.

**install semantic layering (cross-referenced with LIF-006, preventing
the name collision):**

- `make install / uninstall` = **file layer**: copy/remove build
  artifacts (./bin → system or output directories).
- `app service install / uninstall` (LIF-006) = **service-registration
  layer**: generate/remove systemd units.
- Standard deployment flow for service programs: `make install` (place
  the binary) → `app service install` (register for management); each
  layer does its own job and must not substitute for the other.
- `build.sh install` (LIF-005) is the sanctioned upper-layer composite
  of these atomic steps — binary replacement + service restart +
  health check — composing them, never mutating their semantics.

**Standard flow (local development / CI identical):**

```bash
./setup.sh && ./build.sh   # top-level script flow
make build                 # or use native make directly
```

### Forbidden Clauses (red lines)

- ❌ A Go project without a Makefile, forcing everyone to type `go
  build` by hand.
- ❌ Some projects using build.sh while others call cmake scripts
  directly.
- ❌ Arbitrary binary output directories (out/, build/, repo root
  mixed).
- ❌ setup.sh compiling code inside; build.sh apt-installing
  dependencies inside (responsibility mixing).
- ❌ Ad-hoc script names of every flavor: deploy.sh, deps.sh,
  compile.sh.
